# Полное техническое задание (Лабораторная работа №8)

## 1. Общие сведения о проекте
*   **Наименование:** Warehouse Online (WMS).
*   **Назначение:** Веб-приложение для автоматизации складского учёта, контроля остатков и ведения истории поставок.
*   **Стек технологий:** PHP 8+, MySQL, HTML5, CSS3, Vanilla JavaScript.
*   **Среда разработки:** XAMPP, Visual Studio Code (или Блокнот), Git.

## 2. Архитектура приложения
Приложение построено по клиент-серверной архитектуре с генерацией страниц на стороне сервера (SSR). 
Структура проекта разделена на логические слои:
*   **`config/`** — настройки подключения к базе данных.
*   **`app/`** — ядро приложения (класс подключения PDO, функции авторизации и хелперы).
*   **`includes/`** — общие элементы интерфейса (шапка, боковое меню, подвал).
*   **`public/`** — публичные страницы (точки входа), доступные пользователю.
*   **`database/`** — SQL-скрипты для развертывания структуры БД и создания администратора.

## 3. Описание базы данных (6 таблиц)
1.  **users** — пользователи системы (админы и кладовщики). Пароли хранятся в виде хеша Bcrypt.
2.  **categories** — справочник категорий товаров.
3.  **suppliers** — справочник поставщиков.
4.  **products** — номенклатура товаров (артикул, цена, минимальный остаток).
5.  **stock_in** — журнал операций прихода (кто, когда, сколько и от кого принял).
6.  **stock_out** — журнал операций расхода (кто, когда, сколько и по какой причине списал).

Связи реализованы через внешние ключи (Foreign Keys) с правилами `ON DELETE SET NULL` и `ON DELETE CASCADE` для предотвращения появления «битых» данных.

## 4. Реализованный функционал
*   **Авторизация и сессии:** Безопасный вход, хранение сессии, выход из системы. Защита от подделки межсайтовых запросов (CSRF-токены).
*   **Разграничение прав (RBAC):** Роль `admin` имеет доступ к управлению пользователями. Роль `storekeeper` занимается только складскими операциями.
*   **Управление товарами:** Полный CRUD (создание, чтение, обновление, удаление). Автоматическая проверка уникальности артикула (SKU).
*   **Приход/Расход:** Валидация ввода. При расходе происходит проверка остатка (нельзя списать больше, чем есть на складе).
*   **Дашборд:** Аналитика в реальном времени. Вывод общей стоимости склада и товаров, достигших минимального остатка.
*   **Отчётность:** Сводная таблица остатков с подсчётом итоговой суммы.

## 5. Безопасность
*   Все SQL-запросы выполняются через **PDO с подготовленными выражениями (Prepared Statements)**, что исключает SQL-инъекции.
*   Вывод данных в HTML экранируется через функцию `htmlspecialchars` (защита от XSS).
*   Для изменения данных используются только POST-запросы, защищённые CSRF-токенами.
